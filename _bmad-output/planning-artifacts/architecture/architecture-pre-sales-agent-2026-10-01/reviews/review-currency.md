## Flagged (need spine change)
1. **F1 (WRONG) AD-8 "sets an explicit num_ctx" through the OpenAI-compatible API.** Ollama docs (docs.ollama.com/api/openai-compatibility): "The OpenAI API does not have a way of setting the context size for a model." Workaround is a Modelfile `PARAMETER num_ctx`, then call the derived model name. Other options: server-wide `OLLAMA_CONTEXT_LENGTH`, or the native /api/chat `options.num_ctx`. Defaults are VRAM-dependent (docs.ollama.com/context-length): <24 GiB = 4k, 24-48 GiB = 32k, >=48 GiB = 256k. So "never Ollama's default" cannot be met via /v1. Fix: the Ollama adapter must either bake num_ctx into per-agent Modelfile variants (registry stores the derived model tag) or use the native API for chat, and the OpenAI-compat path is only for portability. Also set OLLAMA_CONTEXT_LENGTH as a safety net and verify with `ollama ps`. Note a larger default than assumed (32k/256k) inflates KV cache and VRAM, which hits AD-22 sizing. memlog says "Default ctx 4096 must be overridden", which is only true under 24 GiB.
2. **F2 (STALE) HubSpot API 2026-03.** HubSpot docs (developers.hubspot.com/docs/api-reference/latest/overview) list 2026-09 as latest, 2026-03 as previous; previous versions work until their end-of-life date. For a new integration the docs say use the latest. Fix: pin 2026-09 (or make it config, and record EOL date of 2026-03 once published). URL form `/crm/objects/2026-09/...` confirmed; httpx choice is fine. EOL date not confirmed by me.
3. **F3 (UNDERSPECIFIED) AD-6 checkpointer "in schema orchestration_checkpoints".** PostgresSaver (langgraph-checkpoint-postgres 3.1.2, source `__init__.py`) has no schema parameter. Tables are unqualified, so schema comes from connection `search_path`. Fix: say so (connection option `-c search_path=orchestration_checkpoints`, run `setup()` from the migrate step with that connection; autocommit=True and row_factory=dict_row required per memlog). Also the package depends on psycopg-pool and langgraph-checkpoint>=4.1,<5, so add psycopg-pool to the stack.
4. **F4 (UNDERSPECIFIED) AD-14 "one HNSW index per active model".** pgvector HNSW needs fixed dimensions; `vector` HNSW max is 2000 dims (bge-m3 1024 is fine). A column holding mixed dims needs partial, expression indexes: `CREATE INDEX ... USING hnsw ((embedding::vector(1024)) vector_cosine_ops) WHERE embedding_model='bge-m3'`, and queries must use the same cast expression and filter or the index is not used. Source: github.com/pgvector/pgvector README (expression + partial indexes). Spell this out.

## Confirmed correct
- Registry versions match exactly (PyPI/npm JSON, 2026-10-01): FastAPI 0.142.2, Pydantic 2.13.5, SQLAlchemy 2.1.1, Alembic 1.20.0, psycopg 3.3.6, LangGraph 1.2.12, langgraph-checkpoint-postgres 3.1.2, pgvector 0.5.0, docling 2.131.0, pymupdf 1.28.2, extract-msg 0.56.1, opentelemetry-sdk 1.45.0, Next.js 16.3.8, React 19.3.0, Tailwind 4.3.3, shadcn 4.21.0, @azure/msal-browser 5.23.0 (latest tag; 4.30.0 is the lts tag). Several are only days old (FastAPI 2026-09-30), so pin with a lockfile.
- LangGraph `interrupt()` + `Command(resume=...)` need a checkpointer and a stable thread_id; the node re-runs from its start on resume, so side effects before interrupt must be idempotent (docs.langchain.com/oss/python/langgraph/interrupts). This supports AD-6/AD-7 idempotency keys; state it in AD-7 explicitly.
- Ollama structured output: native `format` with a JSON schema, and OpenAI-style `response_format` json_schema are both documented (docs.ollama.com/capabilities/structured-outputs). The openai-compat page only mentions JSON mode, so test `response_format` json_schema against the pinned version in CI. Docs advise also putting the schema in the prompt and using low temperature.
- Ollama `/v1/embeddings` supports model, input, encoding_format, dimensions (no `user`). Chat endpoint lacks tool_choice and logit_bias.
- bge-m3: 1024 dims, 8192 max tokens, MIT licence, 567M params, ~1.2 GB (HF model card BAAI/bge-m3; ollama.com/library/bge-m3 gives 8K ctx and size but not dims or licence). Spine does not state dims; AD-14 stores them per vector, good.
- gpt-oss:20b: Apache 2.0, 128K context, MXFP4, 14 GB download, runs in ~16 GB memory (ollama.com/library/gpt-oss). Fits the 24 GB minimum. It is a reasoning model, so token budgets must include reasoning tokens; chain-of-thought must not be stored (AD-12 already covers this).
